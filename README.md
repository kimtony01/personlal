# 해상 항로 리스크 조기경보 시스템 (Flask)

**운항 중인 선박과 출발·도착항을 등록**하면, 그 배가 앞으로 지날 **남은 경로 전체**를 한 시간마다 확인합니다.
문제가 예측되면 **대체 노선과 함께 경고 메일**을 보냅니다.

- 경로상 감시 해협(호르무즈, 수에즈·홍해, 말라카, 파나마)의 위험 점수 — 뉴스·기상·지정학 지수로 계산
- 경로 전체의 기상 — 배가 각 지점에 **도착할 예상 시각**의 파고·풍속 예보
- MMSI 로 등록하면 AIS 로 현재 위치를 추적해, 이미 지난 구간은 빼고 남은 경로만 봅니다

## 실행 방법

```bash
pip install -r requirements.txt
cp .env.example .env        # API 키, SMTP 정보 입력
flask run                   # 또는: python app.py / python project.py
```

- 브라우저에서 http://127.0.0.1:5000 을 엽니다.
- 서버가 시작되면 스케줄러가 바로 1회 수집·계산을 하고(1~2분 소요), 이후 `config.toml` 의 간격대로 반복합니다.
  첫 계산이 끝나기 전에는 화면에 '데이터 수집 중'이 표시됩니다.
- 디버그 모드: `FLASK_DEBUG=1 python app.py` 또는 `flask --app app run --debug` (리로더가 있어도 스케줄러는 한 번만 뜹니다).
- 웹 서버 없이 수집·계산만 1회 실행: `python scheduler.py`
- 결과는 `risk_monitor.db` (SQLite) 에 저장됩니다.

## 배포 (Render 무료 + Neon Postgres 무료)

1. **Neon** (https://neon.tech) 에서 프로젝트 생성 → 연결 문자열(`postgresql://...`) 복사. 리전은 Singapore 권장
2. 로컬 기록 옮기기 (1회): `$env:DATABASE_URL="postgresql://..."; python migrate_to_pg.py`
3. **Render** (https://render.com) → New → Blueprint → 이 GitHub 저장소 선택 (`render.yaml` 사용)
   → `DATABASE_URL`, `NEWSAPI_KEY`, `AISSTREAM_API_KEY`, `SMTP_FROM`, `ALERT_RECIPIENTS`, `BREVO_API_KEY` 입력
4. **cron-job.org** 에서 `https://<앱주소>/healthz` 를 10분마다 호출 (무료 플랜은 15분간 요청이 없으면 잠듦)

- `DATABASE_URL` 이 있으면 Postgres, 없으면 로컬 SQLite 를 씁니다. AIS 스냅샷·항적도 Postgres 사용 시 DB(`kv_store`)에 저장됩니다.
- Render 무료는 SMTP 포트가 막혀 있을 수 있어 메일은 Brevo HTTP API(`BREVO_API_KEY`)로 보냅니다.
- gunicorn 워커는 1개여야 합니다 (워커마다 스케줄러가 떠서 메일이 중복 발송됨).

## 화면 구성

**첫 화면**

0. **내 운항 감시** — 등록한 운항 목록(등급·첫 번째 문제·추천 대안)과 '+ 운항 등록' 폼. 줄을 누르면 운항 상세로 이동
1. **해협 카드** — 5개 해협의 등급(아이콘+글자+색)·점수·직전 계산 대비 변화. 카드를 누르면 그 해협을 봅니다.
2. **현재 판정** — 점수와 정상/경고/심각 구간 막대, "경고까지 몇 점 남았는지 / 가장 큰 요인" 한 문장 설명
3. **점수는 이렇게 나왔습니다** — 지표별 기여 점수 막대 (막대 길이 = 비중, 채워진 부분 = 이번 점수)
4. **점수 추이 / 관련 뉴스** — 실제 계산 기록, 강한 키워드가 걸린 주요 기사
5. **대체 항로 비교** — 한 줄 결론, 경로 지도, 순위표(현 항로 대비 비용·일수 차이), 비용 가정 입력, 메모·출처
6. **선박 추적** — 사이드바에서 선박명/MMSI 를 검색하면 표시

**운항 상세 (`/voyage/<번호>`)**

- 결론 한 줄(등급, 문제 수, 추천 대안)과 기준 위치·남은 거리·일수·도착 예상
- 지도: 남은 경로(실선), 대체 노선(점선), 기상 위험 지점(▲), 감시 해협(×), 현재 위치(★)
- 예측된 문제 목록, 경로상 기상 예보 그래프(도착 예상 시각 기준 파고), 대체 노선 표, 알림 기록
- '지금 다시 확인'(즉시 재평가), '운항 종료'(감시 중단)

## 운항 감시 방식

1. **기준 위치**: 등록 MMSI 의 AIS 위치가 48시간 이내면 그 위치, 아니면 출발항.
   등록된 MMSI 는 AIS 수집 때 따로 구독(`FiltersShipMMSI`)해서 위치를 더 확실히 잡습니다.
2. **남은 경로**: `sea_network.py` 의 해상 항로망(주요 해역 경유점 약 100개)에서 기준 위치 → 도착항 최단 경로.
   어느 항구 조합이든 계산되며, 지나는 감시 해협이 순서대로 나옵니다.
   예: 라스타누라→울산 = 호르무즈·말라카, 부산→로테르담 = 말라카·수에즈, 부산→뉴욕 = 파나마.
3. **문제 예측**
   - 해협: 경로상 해협의 최신 판정이 경고·심각이면 문제
   - 기상: 남은 경로를 250해리 간격으로 나눠, 배가 도착할 예상 시각(거리 ÷ 속력)의 파고·풍속을 Open-Meteo 에서 조회.
     파고 4 m / 풍속 34 kn 이상 = 경고, 6 m / 48 kn 이상 = 심각. 예보가 8일까지라 그 안에 도달하는 구간만 확인합니다.
4. **대체 노선** (문제가 있을 때만)
   - 위험 해협을 뺀 경로 + 그 경로가 지나는 다른 해협까지 뺀 두 번째 경로 (예: 수에즈 위험 → 파나마 경유 / 희망봉 경유)
   - 호르무즈 위험인데 페르시아만 안에서 출발·도착: 얀부·푸자이라 선적지(하역지) 변경 (EIA 파이프라인 용량 메모 포함)
   - 파나마 위험 + 미 동안 도착: 미 서안(롱비치) 하역 + 철도 6일 (USDA)
   - 기상 위험: 위험 구간을 지나지 않는 경로, 출발·진입을 12~72시간 늦췄을 때 위험이 사라지는 최소 지연 시간
   - 위험이 낮은 순 → 일수가 짧은 순으로 정렬. 일일 운항비를 넣으면 비용 차이도 표시
5. **경고 메일**: 이슈(해협별, 기상)마다 등급이 새로 생기거나 올라갈 때만 운항별 수신자에게 보냅니다.
   같은 이슈는 6시간 안에 같은 등급 이하로 다시 보내지 않습니다.
   메일에는 선박·항로·기준 위치·남은 거리·도착 예상, 예측된 문제와 근거, 대체 노선(거리·일수·경유 해협 상태)이 들어갑니다.

## 판정 방식

규칙 기반 점수(0~100) 하나로 판정합니다. 랜덤포레스트는 가상 데이터로 학습되어 규칙을 흉내 내는 수준이었기 때문에 제거했습니다.

```
점수 = Σ (지표 정규화값 0~1 × 지표 최대 점수)
정상 < 40 ≤ 경고 < 65 ≤ 심각        (기준점은 가정값)
```

| 지표 | 최대 점수(가정값) | 정규화 |
|---|---|---|
| 뉴스 건수 | 30 | 상대값 = (최근 7일 일평균 × 키워드 가중) ÷ (최근 30일 일평균). 1.0배 이하 0점, 3.0배 이상 만점 |
| 뉴스 증가율 | 15 | (최근 7일 − 직전 7일) ÷ 직전 7일. 0% 이하 0점, +100% 이상 만점 |
| 기상 위협 | 20 | 파고 2.5→6.0 m, 풍속 22→48 kn 사이를 직선으로 0→1, 둘 중 큰 값 |
| 지정학 위협 지수 | 35 | (지수 − 1) ÷ 4 |
| AIS 통항량 감소 | 0 (비활성) | 무료 AIS 2분 표본은 해협 안 선박이 0~수 척이라 신뢰할 수 없어 꺼 둠. 수집 기록은 계속 쌓이며, `config.toml` 의 `ais_drop` 에 점수를 주면 다시 켜짐 |

- **키워드 가중**: 기사 제목+요약에 봉쇄(blockade)·공격(attack)·나포(seize, hijack)·제재(sanction)·미사일·기뢰(mine) 등이 있으면
  그 기사를 3건으로 셉니다. 최근 7일 기사 표본(최대 100건)의 평균 가중치를 기사 수에 곱합니다.
- **지정학 지수**: 표본 중 강한 키워드 기사 비율로 추천값(1~5)을 계산해 화면에 보여 주고, 사이드바에서 수정할 수 있습니다.
  수정값은 수정 날짜와 함께 저장되고 '추천값으로 되돌리기'로 해제합니다. 북극항로는 기존처럼 계절로 자동 결정합니다.
- 화면의 막대 그래프에서 지표별 기여 점수와 원 지표값을 확인할 수 있습니다.
- 데이터가 없는 지표는 0점으로 처리하고 '데이터 없음'으로 표시합니다.

## 해협 단위 알림 (기본 꺼짐)

운항 단위 경고와 겹치지 않도록 `config.toml` 의 `[alerts] strait_alerts = false` 가 기본입니다. 켜면:

- 위험 계산 때 직전 기록보다 등급이 **올라간 경우에만**(정상→경고, 경고→심각, 정상→심각) 메일을 보냅니다.
- 같은 해협은 마지막 발송 후 `cooldown_hours`(기본 6시간, 가정값) 동안 같은 등급 이하 알림을 보내지 않습니다.
  더 높은 등급으로 올라가면 대기 시간과 상관없이 보냅니다.
- 메일 내용: 해협 이름, 판정 등급, 지표별 기여도, 주요 기사 제목(번역+원문), 마지막으로 저장된 비용값 기준의 대안 순위와
  '○월 ○일 입력값 기준' 표시(저장값이 없으면 '가정값 기준'으로 표시).
- 발송·실패·대기 중 기록은 `alert_log` 테이블과 사이드바에 남습니다.

## 가중치·기준점 설정 방법

`config.toml` 을 수정하고 앱을 다시 시작합니다.

- `[score]` 지표별 최대 점수 / `[thresholds]` 경고·심각 기준점
- `[news]` 상대값·증가율 만점 기준, 강한 키워드 목록과 가중치, 지정학 지수 추천 경계값
- `[weather]` 파고·풍속 경계값, 예보 범위 / `[ais]` 감소 판정 기준
- `[schedule]` 수집·계산 주기 / `[alerts]` 대기 시간
- `[scenario.*]` 대안 비교용 속력과 비용 기본값

|---|---|---|
| 호르무즈 | 라스타누라 → 울산 VLCC (기본 화면) | 현 항로 유지, 사우디 동서 파이프라인→얀부 선적, UAE 하브샨–푸자이라 파이프라인→푸자이라 선적, 비중동 원유로 공급처 전환 |
| 수에즈·홍해 | 부산 → 로테르담 | 수에즈 통과(보험료 감수), 희망봉 우회 |
| 말라카 | 콜롬보 → 부산 | 현 항로 유지, 순다 해협, 롬복–마카사르 해협 |
| 파나마 | 부산 → 뉴욕 | 현 항로 유지, 수에즈 경유, 미 서안(LA) 하역 후 철도 |
| 북극항로 | 부산 → 로테르담 | 북극항로, 수에즈 경유 |

- 총비용 = 해상 일수 × (일일 용선료 + 일일 연료 소모량 × 연료 단가) + 선체가액 × 전쟁위험 보험료율 + 기타 비용
- 용선료, 연료 단가, 연료 소모량, 선체가액, 대안별 보험료율·기타 비용은 화면에서 입력합니다. 입력하면 fetch 로 서버에 저장되고
  총비용·순위가 페이지 새로고침 없이 다시 계산됩니다. 마지막 입력값과 입력 날짜는 SQLite 에 저장됩니다.

## 가정값 목록

출처 없이 정한 값이며, 화면과 `config.toml` 에 '가정값'으로 표시되어 있습니다.

- 지표별 최대 점수(30/15/20/35)와 판정 기준점(경고 40, 심각 65)
- 뉴스 상대값 만점 3.0배, 증가율 만점 +100%, 강한 키워드 가중치 3.0, 지정학 지수 추천 경계값(5/15/30/50%)
- 기상 경계값의 '0점 시작·만점' 사용 방식 (경계값 자체는 WMO 해상상태 코드·보퍼트 풍력계급)
- AIS 감소 기준(70%/30%), 평소값 최소 기록 수 5, 알림 대기 시간 6시간
- 북극항로 월별 계절 지수 (기존 코드에서 유지)
- 대안 비교의 선박 속력(VLCC 13노트, 북극 10노트, 말라카·파나마 16노트. 수에즈 시나리오 16노트는 Port Economics 비교 기준과 동일)
- 비용 기본값 전부(용선료, 연료 단가·소모량, 선체가액, 보험료율, 통항료 등 기타 비용) — 저장된 입력값이 없을 때만 사용

## 남아 있는 한계

- **운항 경로는 근사선**: 항로망은 주요 항로를 단순화한 경유점 연결이라, 실제 항로·거리와 차이가 있고 선박 크기(흘수)·운하 통과 가능 여부를
  따지지 않습니다(예: VLCC 는 파나마를 못 지나지만 항로망은 구분하지 않음). 대체 노선의 비용에는 통항료·보험료·파이프라인 이용료가 빠져 있습니다.
- **현재 위치**: 무료 AIS(지상국 기반)라 대양 한가운데서는 위치가 잘 안 잡힙니다. 위치가 48시간 넘게 없으면 출발항 기준으로 계산합니다.
- **기상 예보 범위**: 8일 안에 도달하는 구간만 확인합니다. 긴 항해의 뒤쪽 구간은 시간이 지나 가까워지면 확인됩니다.
- **도착 예상 시각**은 등록 속력으로 단순 계산한 값이며, 기항·대기·감속은 반영하지 않습니다.

- **거리는 근사값**: 대안별 거리는 지도에 그리는 경유점 좌표를 이어 계산한 값입니다. 항구 간 정확한 항해 거리를 공개적으로 확인할 수 없는 구간이 많아
  지어내지 않고 근사 계산을 사용했습니다. 검증용으로 부산→로테르담 수에즈 경유가 약 10,860해리(공개 자료 상하이→로테르담 10,600해리),
  희망봉 경유가 약 14,480해리(13,800해리)로 비슷한 수준입니다.
- **파이프라인 대안**: 파이프라인 이용료, 터미널 대기, 실제 여유 용량 확보 가능성은 계산에 없습니다. 푸자이라안은 UAE 원유 대체 구매를 뜻합니다.
- **공급처 전환**: 유종 차이와 원유 가격 차이는 '기타 비용'에 직접 입력해야 합니다.
- **NewsAPI**: 무료 요금제는 기사 검색 기간과 요청 수 제한이 있고, 키워드 검색이라 관련 없는 기사도 섞입니다(예: 'mine'이 광산 기사에도 걸릴 수 있음).
  상대값은 같은 30일 창 안의 비교라, 위기가 한 달 넘게 지속되면 뉴스 지표는 다시 낮아집니다(지속 위험은 지정학 지수로 반영).
- **AIS**: 무료 AISStream 을 짧게 구독한 표본이라 해협 구역 선박 수가 적고 수집 시간에 따라 흔들려 점수에서는 뺐습니다. 선박 추적(지도) 용도로만 씁니다. 이번 수집에 안 잡힌 선박은 마지막 수신 위치로 표시합니다.
- **기상**: 파고·풍속만 봅니다. 파나마 운하의 가뭄(가툰 호수 수위), 북극 해빙 농도 같은 해협별 핵심 요인은 반영하지 않습니다.
- **추이 그래프**: 실제 계산 기록만 쓰므로 초기에는 '데이터 수집 중'이 표시됩니다. 서버가 꺼져 있던 시간의 기록은 없습니다.
- 스케줄러는 웹 서버 프로세스 안에서 돕니다. gunicorn 등 다중 워커로 배포할 때는 `SCHEDULER_ENABLED=0` 으로 웹을 띄우고
  스케줄러는 별도 프로세스 하나에서만 실행해야 중복 알림을 막을 수 있습니다.
- 예전 Streamlit 버전(`project.py`)은 Flask 버전으로 대체되었습니다. 이전 코드는 git 기록에서 확인할 수 있습니다.
